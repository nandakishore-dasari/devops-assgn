
## Task 1: Understanding Soft Links and Hard Links

Linux provides two common ways to create links to files: symbolic (soft) links and hard links.

### Soft Link

A soft link is a reference to another file or path. It is similar to a shortcut because it stores the location of the file it points to. If the original file is removed or moved, the symbolic link can no longer access it.

A symbolic link has its own inode and does not directly represent the original file's data.

### Hard Link

A hard link is another directory entry that refers to the same underlying file data. The original file and the hard link therefore point to the same inode.

Even if the original filename is deleted, the data remains accessible through the hard link as long as at least one hard link still exists.

### Practical Experiment

I first created a file to use for testing:

echo "Testing out Linux links for DevOps" > original.txt

I then created one hard link and one symbolic link:

ln original.txt hard_link.txt
ln -s original.txt soft_link.txt

To compare the links, I checked their inode numbers:

ls -li

Example output:

1458291 -rw-r--r-- 2 abhiroop abhiroop 35 Sep 3 18:00 hard_link.txt
1458291 -rw-r--r-- 2 abhiroop abhiroop 35 Sep 3 18:00 original.txt
1458299 lrwxrwxrwx 1 abhiroop abhiroop 12 Sep 3 18:01 soft_link.txt -> original.txt

### Observation

The important difference can be seen from the inode numbers. original.txt and hard_link.txt have the same inode number, which means they reference the same file data.

The symbolic link has a separate inode and stores a reference to original.txt.

### What Happens When the Original File Is Deleted?

I tested the behavior by removing the original file:

rm original.txt

The hard link can still be used:

cat hard_link.txt

The contents are still available because the hard link refers directly to the same underlying file.

The symbolic link behaves differently:

cat soft_link.txt

This results in a "No such file or directory" error because the path stored in the symbolic link no longer points to an existing file.

Another difference is that hard links normally have to remain within the same filesystem, whereas symbolic links can reference locations on different filesystems.

## Task 2: Difference Between adduser and useradd

Both commands can be used to create Linux users, but they provide different levels of interaction.

### useradd

useradd is a lower-level Linux utility used for creating user accounts. It provides basic account creation functionality and usually requires additional options when a home directory, password, or specific shell needs to be configured.

Because of its straightforward and non-interactive behavior, it is useful when creating users through scripts or automated processes.

### adduser

adduser provides a more user-friendly interface for creating accounts, especially on Ubuntu-based systems. It guides the administrator through several steps, including setting a password and entering optional user information.

For interactive user creation, I found adduser easier to work with.

### Creating a Test Account

I created a test user with:

sudo adduser devtestuser

The command prompted me for a password and additional account information.

Example output:

After creating the account, I checked the user information in /etc/passwd. This confirmed that the account had been created successfully and had a Bash shell configured.

## Task 3: Using journalctl

journalctl is a command-line utility for viewing system logs on Linux systems that use systemd.

Instead of checking individual log files manually, journalctl provides a central way to search and inspect messages generated by the operating system and different services.

### Commands Practiced

The basic command:

journalctl

displays available journal entries. On a busy system, this can produce a large amount of output.

To view messages associated with the current boot:

journalctl -b

To continuously watch for new log entries:

journalctl -f

The follow option is particularly useful when troubleshooting a service because new log messages appear as they are generated.

### Viewing Logs for a Particular Service

I also practiced filtering the journal for a specific service.

For example:

sudo journalctl -u ssh -n 15

Here, -u ssh selects the SSH service, while -n 15 limits the output to the latest 15 entries.

This makes it easier to examine recent service activity without displaying the entire system journal.

## Task 4: Linux Command Cheat Sheet

During the exercises, I practiced several commands that are useful for everyday Linux administration and DevOps work.

### Directory Navigation

- pwd — Displays the full path of the current working directory.
- ls -la — Shows files and directories, including hidden items, together with detailed information.
- cd /path/ — Moves the terminal to a specified directory.

### Creating and Managing Files

- mkdir -p project/src — Creates the requested directory structure, including missing parent directories.
- touch newfile.txt — Creates an empty file if it does not already exist.
- cp -r folder1 folder2 — Recursively copies a directory and its contents.
- mv file.txt /new/path/ — Moves a file or can be used to rename it.
- rm -rf folder/ — Removes a directory and its contents. This should be used carefully because the deletion is forceful.

### Viewing File Contents

- cat file.txt — Displays the complete contents of a file.
- head -n 10 file.txt — Displays the first 10 lines.
- tail -n 10 file.txt — Displays the last 10 lines.

### File Permissions and Ownership

- chmod +x script.sh — Adds execute permission to a script.
- chown user:group file.txt — Changes the ownership and group of a file.

### Checking System Resources

- top — Displays running processes and their resource usage in real time.
- htop — Provides an interactive alternative to top when installed.
- df -h — Displays filesystem disk usage in an easier-to-read format.
- free -h — Shows available and used RAM and swap memory.
